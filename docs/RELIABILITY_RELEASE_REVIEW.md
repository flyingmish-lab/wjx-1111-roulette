# Надёжность прокруток и учёт выдачи

Подготовлено 20 ноября 2026 года по результатам проверки перед запуском. Публикация ещё не выполнена. Даты пользователь выставляет самостоятельно; изменения не содержат новых дат, вероятностей или дневных лимитов.

## Поведение

- Каждая реальная и тестовая прокрутка получает случайный UUID. В базе ключ состоит из Telegram ID и UUID. Сохранение прокрутки и результата операции выполняется в одной транзакции под существующей блокировкой участника. Повторы возвращают исходный результат, включая повтор после завершения периода или расходования остатка. Один UUID нельзя переключить между реальным и тестовым режимом.
- При обрыве/таймауте запрос остаётся неподтверждённым. Вместо новой прокрутки показывается «Проверить результат». Повтор использует тот же UUID. При доступном локальном хранилище номер незавершённой операции переживает перезапуск вкладки; Telegram initData, пароли и токены туда не записываются.
- Один ответ состояния содержит расписание, серверное время, московскую дату, попытки, дневную историю реальных прокруток, сводку призов и результат незавершённой операции. Первоначальные регистрация и два отдельных запроса состояния заменены одним `status`; он по-прежнему регистрирует проверенного Telegram-пользователя.
- Сводка призов и дневная история загружаются из базы. На новом устройстве и при повреждённом/запрещённом localStorage они доступны после загрузки. Старые локальные ключи истории больше не определяют интерфейс и не удаляются этой доработкой.
- На запросы установлен предел ожидания 15 секунд. При ошибке загрузки есть сообщение и «Повторить загрузку»; новые прокрутки до загрузки блокируются. Сохранённый результат показывается независимо от успеха анимации.
- Состояние обновляется при возвращении в приложение, восстановлении сети и раз в минуту в видимой вкладке. Изменение московского дня, настроек дат и лимитов не требует перезапуска. Вычисление статуса периода опирается на время сервера и прошедшее монотонное время, а не на часы телефона.
- После окончания периода «Забрать приз» по-прежнему только открывает чат менеджера. Тестовый режим не создаёт призов к выдаче.
- В карточке участника показаны выданные призы и остаток. После окончания розыгрыша администратор может нажать «Отметить выдачу всех оставшихся призов». Отметка привязана к ID каждой реальной выигрышной прокрутки; повторные и одновременные вызовы не создают повторных отметок. В базе сохраняются время и хеш административной сессии; пароль/токен не сохраняются. Нажимать кнопку следует после фактической выдачи всего остатка. Частичная выдача и отмена ошибочной отметки в этот выпуск не входят.

## Изменения базы

Миграция `202611200004_reliable_spins.sql` добавляет таблицу `wjx_spin_operations`, транзакционную функцию `wjx_perform_spin` и функцию согласованного чтения `wjx_player_state`.

Миграция `202611200005_prize_delivery.sql` добавляет таблицу `wjx_prize_deliveries`, функцию отметки выдачи и поля выдачи в существующую сводку участника. Доступ браузерных ролей к новым таблицам и функциям закрыт; API проверяет Telegram initData либо парольную административную сессию.

Миграции не удаляют и не переписывают старые результаты, участников, даты, шансы, остатки и настройки. Уже существующие выигрыши остаются без отметки выдачи до явного действия администратора. Если по ним уже были реальные выдачи, их следует учесть отдельно при начале работы с новым реестром.

## Проверки

`npm test`: **41 тест прошёл**. `npm run check`: проверены все три Edge Functions. `git diff --check` не обнаружил ошибок пробелов.

Новые проверки охватывают:

- 20 повторов одного UUID, одно списание; независимость одного UUID у разных участников; запрет смены режима.
- Восстановление результата после окончания события и после ошибки чтения состояния уже сохранённой операции.
- SQL-права новых объектов, отсутствие записи операции при откате и сохранение исходных игровых данных.
- Повторную/параллельную отметку выдачи, исключение тестов, пустых исходов и результатов вне периода; запрет выдачи до окончания.
- Первую загрузку без сети, кнопку повтора и один согласованный запрос.
- Потерю ответа после сохранения, восстановление тем же ID и восстановление при старте/возвращении сети.
- Повреждённое и полностью заблокированное хранилище, сбой анимации, таймаут запроса.
- Неверные часы устройства, обновление истории после московской полуночи, старые WebView без `crypto.randomUUID`.
- Карточку выдачи в админке, административную авторизацию нового API и сохранение прежних сценариев игры.

SQL исполнялся на PGlite, API — с подменённым транспортом, интерфейс — в jsdom. PGlite последовательно выполняет обращения; эта проверка не заменяет нагрузочный тест нескольких настоящих соединений. Визуальный локальный предпросмотр не удалось открыть в доступном браузере: адрес локального сервера недоступен. Визуальную проверку на телефонах и проверку рабочего API следует выполнить при согласованном выпуске. Боевые прокрутки и выдачи для тестов не выполнялись.

Выпуск требует отдельного подтверждения владельца. Резерв призового фонда, аварийная пауза и полноценный нагрузочный тест остаются отдельными задачами; они не добавлены скрыто в этот пакет.
