# Только реальные прокрутки и административный сброс

Подготовлено локально, без применения к Supabase и без публикации. Требуется подтверждение владельца.

## Согласованное поведение

Тестовый режим убран из игры, админки и доступных серверных операций. Назначенные ранее балансы больше не переключают рычаг в тестовый режим и не обходят расписание. Старые тестовые записи/балансы сохраняются как архив; новые тестовые прокрутки и изменение этих балансов через API/SQL от имени service_role запрещены.

В браузерной админке можно найти участника по имени, username или Telegram ID и нажать «Сбросить прокрутки за сегодня». Сброс возвращает текущий дневной остаток из настройки daily_spins (обычно 3). Пользователь снова получает реальный дневной набор попыток. Уже выигранные призы, UUID результатов, история, отметки выдачи и расход глобального дневного запаса призов сохраняются. Сброс не открывает игру вне расписания, во время паузы или без подписки.

Игрок может нажать «Обновить попытки» возле сообщения об исчерпанном дневном лимите либо заново открыть Mini App. Обновление только читает состояние и не создаёт прокрутку. Сохранённые неподтверждённые реальные операции продолжают восстанавливаться по прежним UUID; старые pending-запросы тестового режима больше не воспроизводятся.

## Реализация

Миграция 010 добавляет приватную RLS-таблицу аудита wjx_admin_spin_resets. В ней сохраняются UUID сброса, участник, московская дата, последний номер сохранённой прокрутки на момент сброса и хеш проверенной административной сессии. Пароль, секреты и сам токен не записываются в аудит и не возвращаются игроку.

Ничего не удаляется: счётчик доступных попыток и текущая история на странице игры учитывают только записи после последней отметки сброса за текущую московскую дату. Общая история выигрышей и дневной запас призов по-прежнему учитывают все реальные записи.

Сохранённые номера слотов монотонно увеличиваются через сбросы, чтобы исходный уникальный ключ `(telegram_id, spin_date, spin_number)` продолжал защищать записи. CHECK хранилища расширяется до допустимого положительного smallint (32767); сервер отдельно ограничивает каждый выделенный набор текущим daily_spins 1–20. В ответе игроку и текущей истории номер показывается относительно последнего сброса.

Прокрутки и сбросы используют один advisory lock участника. Сброс имеет UUID: повтор после сетевого сбоя возвращает прежнее подтверждение, не давая новый набор попыток. Несовпадение участника с UUID другого сброса отклоняется. Повтор вчерашнего сброса не обнуляет сегодняшние прокрутки. Откат транзакции не меняет остаток.

Админка хранит только несекретный UUID незавершённого сброса в памяти/Session Storage. При потере ответа или ошибке обновления списка пользователей повторяет тот же UUID. При успешном завершении очищает его. Поиск, текущие остатки и сброс требуют действующей браузерной парольной сессии; Telegram ID сам по себе прав не даёт.

## Проверки

- Новые SQL-тесты: сохранность призов и записей, восстановление попыток, повтор UUID после новой прокрутки, отдельные участники/московские дни, откат, повторные сбросы и более 20 сохранённых слотов без нарушения уникальности, пауза/расписание, запрет старых тестовых RPC и прав записи в архив.
- API-тесты: отказ Telegram-only и неверным сессиям, валидация участника и UUID, передача проверенного хеша сессии только сервером, отключение старых тестовых действий.
- UI-тесты: реальный режим при старых балансах, отсутствие обхода расписания, игнорирование старого pending-test, кнопка обновления остатка, выбранный пользователь и повтор сброса после потерянного ответа. Существующая защита подписки, UUID-восстановление, дата/время сервера, лимиты призов и мерч остаются покрыты.
- Исторические SQL-тесты старых миграций, в которых тестовый режим ещё существовал, закреплены до миграции 010; новый актуальный режим проверяется отдельно.
- Исправление применено к локально восстановленной копии реальной схемы: прежние записи сохранены, первый реальный спин после сброса получает номер 1 и остаток 2, повтор сброса с тем же UUID остаток не восстанавливает. Все операции только в локальной базе.

Все 87 тестов и проверка типов четырёх Edge Functions прошли. Повтор полной миграции после нескольких сбросов и номеров слотов выше 20 также проверен; миграция 008 сохраняет расширение хранилища, если уже существует аудит 010.

## Порядок выпуска

1. Свежая приватная копия до 010: использовать предыдущую опубликованную версию scripts/backup-export.sql, поскольку таблицы аудита ещё нет. Проверить восстановление.
2. Обновить wjx-roulette. Прежние тестовые запросы станут отклоняться; реальные прокрутки продолжают использовать прежний SQL до применения 010.
3. Применить 010 с транзакционной проверкой сохранности всех прежних игровых записей, архивов, дат, шансов и лимитов. Существующие реальные попытки не сбрасывать автоматически.
4. Опубликовать игру, админку, SQL, тесты и новый backup-export.sql. После 010 экспорт включает новую таблицу аудита. Проверить CI и GitHub Pages.
5. Владелец обновляет Mini App и админку, выбирает пользователя и выполняет нужный сброс. Сам выпуск не сбрасывает ни одного пользователя и не создаёт реальных призовых операций.
