# Команды Telegram-бота WJX

20 ноября 2026 года опубликованы новая функция, API и админка (GitHub main: `2b228b3`). После отдельного подтверждения опубликована безопасная диагностика `wjx-roulette`. Обработчик подключён к `@wjx_1111_roulette_bot`: повторная серверная проверка подтвердила подключение и 0 ожидающих сообщений. Ошибка 503 при повторной проверке не воспроизвелась; её первоначальная причина не установлена. Получение ответов в личном чате проверяет пользователь.

Подготовлено переименование в «WJX Рулетка»: тексты игры и админки, сообщения бота, описания команд. При согласованном выпуске повторное подключение команд также установит публичное имя бота через `setMyName` для русского языка и языка по умолчанию. Username, адрес Mini App, настройки и игровые данные сохраняются. Изменение имени ещё не опубликовано.

Дополнительно подготовлено скрытие информации о тестировании в пользовательском интерфейсе и ответах бота. Панель, переключатель, отдельная кнопка и счётчик тестов удалены; назначенные попытки используются обычным рычагом. Результат сопровождается нейтральным «Прокрутка завершена.» и не попадает в реальные выигрыши. После исчерпания режим не переключается автоматически на реальные попытки в текущем открытом приложении; повторное открытие загружает актуальное назначение с сервера. Назначение и остатки остаются в админ-панели. Это скрытие интерфейса, а не секретность технических данных запросов Mini App.

## Команды в личном чате

| Команда | Ответ |
| --- | --- |
| `/start` | Приветствие, список команд и кнопка открытия Mini App |
| `/play` | Кнопка открытия рулетки; сама команда не расходует попытку |
| `/prizes` | Реальные призы отправителя за настроенный период, выданное количество и остаток |
| `/rules` | Актуальные даты, время по Москве, дневной лимит и правила учёта попыток |
| `/help` | Список команд и ссылка на существующего менеджера `Wjx_wjxx` |

Все пользователи, включая владельца и сотрудника, получают одинаковое поведение. В группе обработчик не публикует личные призы и не отвечает: кнопка Web App предназначена для личного чата с ботом. Аргументы команды, ник и переданный в тексте чужой ID не используются для выбора участника. Команды с аргументом запуска и суффиксом `@имя_бота` поддерживаются.

`/prizes` вызывает существующую серверную сводку только с ID отправителя доверенного Telegram update. Тестовые результаты, пустые исходы и «Без выигрыша» не входят в список. Команды не выполняют прокрутку, назначение тестов, выдачу или регистрацию пользователя; регистрация по-прежнему происходит при первом входе в Mini App. Старые игровые данные, даты, шансы и остатки не меняются.

## Защита и подключение

Новая Edge Function `wjx-telegram-bot` принимает POST от Telegram и проверяет `X-Telegram-Bot-Api-Secret-Token` до чтения данных игрока. Секрет webhook вычисляется HMAC с отдельной меткой назначения из существующего `WJX_ADMIN_SESSION_SECRET` и `TELEGRAM_BOT_TOKEN`. Ни исходные секреты, ни полученный токен не возвращаются браузеру и не записываются в репозиторий/логи. Создавать новый Secret вручную не требуется. При смене токена бота или секрета сессий следует заново подключить команды.

Собственная проверка webhook заменяет проверку Supabase JWT для этой функции (`verify_jwt = false`). Это не отключает проверку источника Telegram в коде. Общий пароль панели не является секретом webhook.

В браузерной админке добавлены «Проверить подключение» и «Подключить команды бота». Оба серверных API требуют действующую административную сессию; Telegram ID владельца доступа к ним не даёт.

Подключение проверяет `getWebhookInfo`. Если уже настроен другой URL webhook, оно прекращается без его замены. Старый URL может содержать чувствительные данные, поэтому он не выводится в браузер. Проверка не обнаруживает внешние процессы `getUpdates`; если такой процесс существует, его работу необходимо согласовать перед переключением на webhook.

При успешном подключении устанавливаются пять команд в стандартной области и области всех личных чатов, для русского и языка по умолчанию. Меню бота показывает команды. `setWebhook` получает URL новой функции, секрет и тип обновлений `message`; `drop_pending_updates` остаётся `false`. Накопленные обновления не удаляются. Повторная настройка этих же параметров допустима. При частичном сетевом сбое следует проверить статус и повторить подключение, а не менять секреты вслепую.

Ответы отправляются стандартным Bot API методом `sendMessage` в JSON-ответе webhook. Форматирование HTML/Markdown не включается. При ошибке базы функция возвращает 503, чтобы Telegram мог повторить доставку, вместо ложного сообщения об отсутствии призов. Повторная доставка может дать повторный информационный ответ, но никогда не расходует попытки и не выдаёт призы. Текст неизвестной команды ведёт к справке.

## Проверка

`npm test`: **50 тестов прошли**. `npm run check`: четыре Edge Functions прошли проверку типов. Прежние игровые, SQL и административные проверки сохранены. Уточнена имитация AbortSignal в старом тесте таймаута, чтобы учитывать прерывание до регистрации обработчика; производственная логика игры не менялась.

Проверены все пять команд, обычный пользователь/владелец/сотрудник, отсутствие записи прокруток, приватность призов, актуальные даты, новый пользователь без результатов, исключение пустых исходов, поддельный webhook, сообщения из группы/от бота/с чужим chat ID, сбои базы и конфигурации, административная авторизация, защита существующего webhook, отсутствие секретов в ответах, подключение из админки и собранная версия обработчика для Supabase Dashboard.

Тесты используют искусственные секреты и подменённый транспорт Telegram. Реальное получение ответа в Telegram можно проверить только после согласованной публикации и подключения обработчика. Подключение через Bot API в production проверено; пользовательский проход по пяти командам здесь не подтверждён.

## Выпуск после подтверждения

1. Опубликовать `wjx-telegram-bot` из `dashboard-dist/wjx-telegram-bot/index.ts`, отключив внешнюю JWT-проверку согласно `supabase/config.toml`. Собственная проверка секрета обязательна и уже находится в коде.
2. Обновить `wjx-roulette` из собранного исходника; опубликовать исходники, сборочный скрипт, тесты, `admin.html` и `admin.js` в GitHub. Новых миграций базы нет.
3. Войти в браузерную панель, нажать «Проверить подключение», затем «Подключить команды бота». При обнаружении другого webhook остановиться и согласовать перенос его функций. Не удалять накопленные сообщения.
4. Пользователь проверяет `/start`, `/play`, `/prizes`, `/rules`, `/help` в своём личном чате с ботом. Для `/play` достаточно проверить открытие Mini App; реальная призовая прокрутка для этой проверки не нужна.

Официальная документация: [Telegram Bot API — setWebhook](https://core.telegram.org/bots/api#setwebhook), [ответ webhook](https://core.telegram.org/bots/api#making-requests-when-getting-updates), [setMyCommands](https://core.telegram.org/bots/api#setmycommands), [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton).
