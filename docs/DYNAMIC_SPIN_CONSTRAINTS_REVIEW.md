# Исправление старого ограничения дат реальных прокруток

Владелец подтвердил публикацию 23 ноября 2026 и уточнил: оставить даты из админки. Миграция применена с проверкой сохранности восьми игровых таблиц и настроек. Перед применением снимок 10 таблиц и 14 функций восстановлен в отдельной локальной базе. Временные интервалы из расписания не удалялись и не менялись.

В живой таблице wjx_spins осталось ограничение wjx_event_dates с фиксированными датами 10–12 ноября 2026. Проверка текущего расписания в wjx_save_spin проходит, но INSERT отклоняется старым CHECK. Транзакция откатывается; UUID операции и попытка не сохраняются. Клиент поэтому предлагает безопасную проверку результата.

23 ноября диагностика для согласованного тестового аккаунта @wjx_tattoo показала 0 сегодняшних реальных прокруток и 0 сохранённых реальных операций. В настройках стояло 23 ноября, 14:10–14:15 МСК, 3 попытки, пауза выключена.

Миграция 008 убирает только устаревший CHECK дат. Текущая дата МСК и активное расписание по-прежнему проверяются серверной функцией в той же транзакции. Доступ anon/authenticated к таблице и RPC не открывается. Другой устаревший CHECK 1–3 заменяется на 1–20, чтобы соответствовать уже поддерживаемой настройке дневного лимита. Фактический лимит участника по-прежнему берётся из roulette_settings и соблюдается под блокировкой.

Существующие участники, прокрутки, призы, UUID, даты и вероятности не удаляются и не редактируются. Новый CHECK проверяет имеющиеся записи, при несовместимости вся миграция откатится.

Проверки:
- Ошибка 23514 / wjx_event_dates воспроизведена на восстановленной приватной копии реальной базы, затем тот же UUID успешно сохранён после миграции и повторён без второго списания. Всё выполнено только локально, без реальной призовой транзакции.
- Добавлены регрессионные тесты с реальными старыми CHECK: отказ до исправления, отсутствие списания/UUID, работа после исправления, идемпотентность, ранний/поздний запуск, 5 настроенных попыток, дневной лимит, пауза, права ролей и сохранение записей.
- Все 72 теста прошли вместе с построением dashboard-dist/release.sql.

После подтверждения: применить миграцию 008 в транзакции с проверкой сохранности данных/настроек, сверить оставшиеся ограничения, затем опубликовать SQL и тесты в GitHub и проверить CI. Серверный JavaScript и клиент менять не требуется. Реальную проверку выполняет владелец через исходную кнопку «Проверить результат» при активном расписании. Новые даты и удаление записей тестового прогона остаются отдельными действиями владельца.
